La compra completa, de extremo a extremo

Es el caso CP-16, el que recorre el flujo que genera ingreso: catálogo, carrito, datos del comprador, resumen de importes y confirmación. La suite lo ejecuta en Chromium, Firefox y WebKit en cada push.

Los 5 defectos encontrados

SauceDemo incluye usuarios rotos a propósito. Eso no cambia el trabajo: hay que dar con el fallo, acotarlo, comprobar que no es una impresión y describirlo de forma que alguien pueda corregirlo sin volver a investigarlo.

El más grave: un campo obligatorio que no se puede rellenar

En HAL-02, lo que se teclea en «Last Name» se escribe en «First Name» y el apellido queda vacío. Como el formulario exige ese campo para continuar, la compra es imposible.

Antes de reportarlo se descartaron las dos explicaciones alternativas: rellenar primero el apellido y después el nombre, y teclear pulsación a pulsación con 60 ms de retardo. En ninguno de los dos casos se puede rellenar el apellido. Un defecto que el equipo de desarrollo cierra como «no reproducible» cuesta más que no haberlo reportado.

Cómo está hecho

Stack Playwright · TypeScript · GitHub Actions
Arquitectura Page Object Model, fixtures de sesión y juegos de datos externalizados. Ningún selector fuera de pages/, ninguna aserción dentro
Navegadores Chromium, Firefox y WebKit: los tres motores de renderizado que existen
Estabilidad Cero esperas fijas, y no por confianza: lo impone una regla que corta la integración continua
Documentación Plan de automatización, matriz de casos, reportes de defecto y política de tests inestables. Un verificador comprueba en cada push que sigan siendo ciertos
